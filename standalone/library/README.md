# 灵感库云端

## 剪映本机联动

网站 `/?view=jianying` 提供视频素材上传、本机剪映入口、成品预览和手动补传。Windows 助手位于 `native/`，站内可下载 ZIP。用 Python 3 运行 `native/install.ps1` 注册当前用户协议和登录启动项；连接码由所有者生成、5 分钟有效且仅可领取一次。设备视频凭证 90 天有效，哈希保存在 D1、原值由 Windows DPAPI 加密保存在本机；所有者可撤销。该凭证仅可读取视频附件、回传成品与报告在线状态，不能读取完整资料库或修改既有笔记。

网站送来的普通视频保存在助手 `data/素材`；打开剪映后仍需在剪映中点击“导入”。不写入剪映私有草稿格式，也不声称嵌入完整剪映编辑器。剪映导出目录设为助手 `data/成品` 后，电脑运行期间自动回传 MP4/WebM 到原有待整理队列，网站关闭仍可同步。单视频 25 MB；检测稳定并取得 Windows 独占读句柄后上传，失败保留原件并重试。同一视频内容去重，重复回传保留标题、笔记和已整理状态。断开连接与最终内容写入使用同一 D1 条件校验。

新增设备表有 Drizzle 迁移，同时所有者访问剪映接口时以固定 DDL `IF NOT EXISTS` 初始化，兼容旧版归档部署；不改动既有库记录。`tests/jianying.test.mjs` 验证授权、过期、撤销、上传竞态和重复回传。
直播与回放新增固定入口 `/?view=live`，下载 Windows 助手后生成配对码、选择官方直播工具的本地录制目录并启动监测。助手监测新录制，文件关闭且稳定 60 秒后自动上传，网络失败保留队列重试，不修改本地原件。推流、账号登录及开播权限在 OBS 或平台官方客户端完成。

根据用户提供的三张参考，直播页提供人物全屏、屏幕加左下角人物、竖屏上屏幕下人物三种布局示意与 OBS 场景包下载。每包含独立场景集合和唯一名称的配置文件目录（`basic.ini`），分别设定 1920×1080 或 1080×1920 画布与输出。导入后须选择自己的摄像头、显示器与声音设备；场景选择仅决定下载内容，不控制本地 OBS。虚拟摄像机仅传视频，平台软件音频需另行设置；本地录制在 OBS 开启。场景 ZIP 和教程经所有者登录后下载，设备凭证不能读取它们。Windows 助手 ZIP 附同一套场景，EXE 归档逻辑保持一致。模板结构按 OBS 官方源码核对，真实设备采集与账号开播由首次设置验收。

直播回放使用专用 8 MiB 分块接口（单文件最大 8 GiB），完成后流式校验完整 SHA-256。D1 保存设备授权和上传进度，R2 保存录像；同一 `content` 记录同时出现在待处理和直播历史，整理后保留历史。配对仅允许追加回放；凭据在电脑使用 Windows DPAPI 加密，云端只存哈希。安装包通过既有受限云同步授权上传，网站检查源码中固定的安装包哈希。浏览器导入需保持页面打开；助手上传无需网页保持打开。

完整网站 ZIP 备份仍有 60 MiB 上限，大回放可以逐个下载。原电脑客户端已补上分段附件下载，避免长回放阻断旧同步。MKV 可保存和下载，网站内播放使用 MP4/WebM；浏览器还需支持录像采用的编码。

个人内容库、素材文件、标签和手动精选周刊。D1 保存记录，R2 保存上传文件与已缓存封面。只有所有者可以管理资料，访客只可访问带随机令牌的单期周刊及该期图片。

## 运行与构建

- Node.js 24，`npm ci` 安装锁定依赖。
- `npm test` 验证数据库合并、周刊快照、附件权限、备份迁移与封面识别。
- `npm run build` 将 `public/` 与 Worker 编译到 `dist/server/index.js`。
- `npm run validate` 检查 Worker 导出。数据库迁移位于 `drizzle/`。
- 通过 Sites 工作流发布，复用 `.openai/hosting.json` 中的站点 ID。

在 Sites 配置 `OWNER_EMAIL` 和不少于 32 字符的随机秘密 `SYNC_TOKEN`。同步凭证只允许同步与附件接口；不得放入网页代码或源代码仓库。浏览器登录由 Sites 提供。

## 数据迁移

本机完整 ZIP 备份经校验后通过 `/api/sync/migrate` 导入，只允许导入空库。保留原始记录、周刊快照、引用附件及 ME.zip 原始 JSON 备份。云端已有内容时拒绝整体覆盖。

电脑服务每分钟以字段级三方合并同步，保留双方新增与无关字段修改，同字段冲突时停下并保留双方副本。电脑关闭时无法读取本机 ME.zip 新内容；云端资料仍可访问。同步使用版本校验防止覆盖云端新修改。

云端单文件上限 25 MB，在线完整备份上限 60 MB。平台链接可能因原站限制而无法自动取得封面或文案，此时页面提示手动补充。周刊由用户明确选择内容并生成，不自动公开私人资料。

## 手机独立采集：云端浏览器（已配置，用户真实样例已通过）

用户已选择电脑关机也可采集的云端方案。普通网页预览不足时，所有者从网页提交的同源 POST 先调用抖音官方无需授权的 `get_iframe_by_video` 接口，取得发布标题与精确匹配视频 ID 的播放器地址；再调用 Cloudflare Browser Run `/browser-run/content` 读取该官方播放器。只提交公开视频 URL，不提交私人笔记、资料库、Cookie 或登录凭据，不自动登录抖音或处理验证码。

需在 **Sites 服务端秘密配置** 中增加 `CLOUDFLARE_BROWSER_ACCOUNT_ID` 和 `CLOUDFLARE_BROWSER_API_TOKEN`。Token 只授予指定 Cloudflare 账号的 **Browser Rendering / Edit** 权限，不使用全局 API Key，不放入网页、Git、聊天或导出备份。`.env.example` 仅记录变量名。通过所有者接口 `/api/capture/status` 查看是否存在配置；`configured: true` 仅表示配置格式有效，不代表已通过真实采集验收。

官方嵌入路径仅接受唯一主播放器直接子节点 `xg-poster` 的封面，并再次校验页面 URL、视频 ID、随机标记和 CDN 域名；推荐图片、头像和二维码不作为封面。`video_title` 原样保留为发布文案，不等同视频口播转写。官方接口不可用时保留先前公开网页路径；若只得到标题仍保留它并提示封面待补。成功取得图片后使用 R2 文件签名、大小校验与备份。单次云浏览器调用上限 45 秒；同一实例内同帖同路径并发请求合并、最多同时执行两条。未开通、授权错误、额度不足、跳转不符和内容缺失都会保留为未完成状态。

2026-09-27 经用户明确确认后，专用 Browser Run Write 令牌已创建并配置至 Sites 环境 revision 2，第 4 版已应用新配置。真实线上采集尚未通过：短链可定位目标视频，但返回未完成提示。直接调用服务商 API 可返回页面 HTML；等待 10/20 秒以及允许媒体加载后，页面仍显示“视频数据加载中”，没有目标 h1、播放器 poster 或匹配视频 ID 的封面实体。HTTP 200 不代表取得了封面与原文。用户样例之前经本机浏览器辅助核实入库，与自动采集能力分别记录；不能用占位图补足验收。

开通顺序：用户登录 Cloudflare → 确认仅 Browser Rendering/Edit 的账号令牌 → 将令牌安全配置到 Sites → 在手机网站粘贴用户真实抖音链接 → 验证来源匹配、完整原文、真实封面及 R2 备份 → 确认整个请求不依赖电脑本机。先使用免费额度，不自动升级套餐。

## 草稿与诊断修复

第 6 版于 2026-09-28 上线设备草稿恢复、重试保护及不含密钥的服务商诊断。关闭或刷新表单后，下次新建/整理同一记录会恢复文字、来源、封面、星级与序号；“丢弃草稿”只移除设备草稿。草稿按编辑前版本逐字段合并，同字段与云端冲突时显示双方内容并要求明确选择，旧版草稿也不静默覆盖；长文不截断，存储不足明确提示。草稿不会自动发布，点击“保存内容”后才同步到云端。重试只补全空字段或未被用户修改的自动结果，不清空已有封面/原文，也不覆盖自己的笔记。解析失败可先保存待补全链接，不生成虚构文案。

服务商错误日志仅保留阶段、耗时、HTTP 状态、数字错误码及固定分类，不输出原始错误文本、HTML、URL 或凭证。第 6 版 35 项回归测试与构建检查通过，原站点发布权限和所有者页面登录均恢复。07:18 UTC 真实线上请求诊断为 request 阶段 redirect 异常，未取得服务商 HTTP 响应。后续改用当前官方 `/browser-run/content` 接口并以 `redirect:manual` 显式拒绝所有 3xx，不转发凭证；真实抖音封面与原文仍待验收。
