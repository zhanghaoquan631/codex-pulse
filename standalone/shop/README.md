# 我的小店

两个独立入口，共用同一套商品、图片、订单和设置：

- 顾客售卖页：`/`，商品目录 `/catalog`，商品详情 `/item/商品编号`。
- 店主管理页：`/manage`，支持手机和电脑浏览器。

## 日常上架

进入管理页，输入管理密码 → 商品管理 → 新增商品 → 上传图片、填写商品名称和配套文字、设置价格 → 发布上架。

购买及发货说明是全店共用的固定模板，会自动附带在每一个商品详情页后面。不需要复制，不会被商品介绍覆盖。原参考页中的相关说明保留原文。

后台的“查看商品”可复制该商品链接；“查看店铺”打开前台。已打开的前台会在后台保存后接收更新，断线时也会在重新打开或恢复连接后读取最新内容。

## 付款与私下沟通

QQ 已设为 **YOUR_QQ**。微信、支付宝分别使用你提供的原始图片，二者不会混用。

顾客填写联系方式 → 选择微信或支付宝 → 创建订单 → 扫码付款 → 点击“我已付款，提交付款信息”。订单会进入后台“待核款”。这一步只是顾客申报付款，不代表系统确认到账。

你核对实际收款后，在订单管理中点“确认收款”，复制客户联系方式私下沟通。处理完后可点“标记已处理”，处理备注可留空。系统不会自动发送卡密、兑换或为客户充值。

店铺设置可更换 QQ、微信号、联系二维码和两种收款码。当前没有提供微信号或加好友二维码，因此这两个字段为空；微信收款码仅作为付款用途。

## 本机打开

需要 Node.js 24。首次运行：

```sh
npm ci
npm run build
npm start
```

售卖页 <http://localhost:8787/>，后台 <http://localhost:8787/manage>。

首次启动会自动生成独立管理密码，保存在项目的 `.env.local` 中 `ADMIN_PASSWORD=` 后面。该文件不会被打进交付包，也不应上传到公开仓库。

同一 Wi-Fi 的手机可以使用启动时显示的局域网地址。电脑需保持运行；Windows 防火墙和无线网络隔离可能阻止手机连接。本地地址不是公网正式网址。

## 正式部署

商店业务现支持两种后端：Node 服务使用持久磁盘保存数据；Sites Worker 使用 D1 保存商品、订单和会话，R2 保存上传图片。不能只把 `dist/client` 上传到静态托管，否则后台、订单、上传都不可用。Worker 的迁移在 `drizzle/`，构建会一并打包；目前尚未正式部署。

首页已包含分类、搜索、商品目录、QQ 联系卡、公告及重置日历。邮件订阅暂未启用，不会收集邮箱或显示虚假的订阅成功。用户指定的预约系统使用 163 SMTP；现有 Sites 托管不支持直接连接 SMTP，且未提供可确认的定时调度能力。需要支持 Node 的公网服务器，或独立 HTTPS 发信服务及调度器，确定后再接入。预约系统原数据和凭据未修改。

在支持 Node 24 的服务器上部署，配置：

```text
ADMIN_PASSWORD=你的独立长密码（至少12位）
PORT=8787
NODE_ENV=production
TRUST_PROXY=true
```

使用反向代理提供 HTTPS（会话使用 Secure cookie）。域名下的 `/api`、`/uploads` 和页面路由都要到同一个 Node 服务。SSE `/api/events` 关闭代理缓冲。管理页与售卖页分别使用 `https://你的域名/manage` 和 `https://你的域名/` 即可。

也可运行附带 Dockerfile，挂载 `/data` 持久卷（默认已设置 `STORE_PATH=/data/store.json`、`UPLOADS_PATH=/data/uploads`）。首次部署数据文件不存在时，使用 `worker/seed.js` 中的公开初始商品和设置初始化，不复制本机订单；已有数据不会被覆盖。之后升级代码时保留这个持久卷。

数据备份：同时备份 `server/data/store.json`、`server/data/subscriptions.json`（启用邮件后才创建）与 `server/uploads/`（或你指定的数据路径）。只运行一个 Node 实例管理这些 JSON 数据库；扩展多实例前应迁移数据库。正式域名和托管环境尚未配置。

## 邮件订阅（Node 服务器）

已实现服务端 SMTP 订阅，但默认关闭，不自动读取预约系统的私密配置。配置项见 `.env.example`：`MAIL_ENABLED=true`、固定的 HTTPS `PUBLIC_ORIGIN`、`SMTP_USER`、`SMTP_PASS`；163 默认 `smtp.163.com:465`。上线前需要确认服务器、填入授权码并进行真实投递验证。不能把本机地址写成正式邮件链接，也不要将密码填入管理页面或聊天。

启用后，服务每分钟检查新动态。订阅者必须打开确认邮件并再次点击确认；GET 链接预览不改变订阅。每封通知包含退订页面，退订时移除邮箱与待发任务。新订阅跳过当时已有记录；同一事件相同状态不重复建任务，预告变成确认仍可通知。失败按退避策略重试，8 次后在后台“店铺设置 → 重置邮件通知”显示失败数量，可手动重新排队。页面只展示统计，不公开订阅邮箱或 SMTP 错误内容。

每个邮箱确认邮件间隔至少 10 分钟，全站每日最多 100 封确认邮件；确认链接有效期 24 小时。仅支持单实例和持久磁盘。SMTP 已接受邮件但保存结果前如果断电，恢复重试可能重复投递；固定 Message-ID 只帮助去重，不承诺绝对只收到一次。退订无法撤回已经开始发送的邮件。
